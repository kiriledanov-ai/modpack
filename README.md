# Lunacy для mope.io

Lunacy — расширение Manifest V3 для Chrome/Edge с отдельным онлайн-сервером. Владелец **`@cleverok`** уже включён в первоначальные данные сервера с ролью **Creator**.

## Что внутри

- Зум до **25× отдаления** (`0.04`) и колесо мыши.
- Независимый множитель клиентской области рендера от 100% до 300%.
- Перетаскиваемый HUD, скрытие/открытие клавишей **N**.
- Кометы, кристаллы, два пистолетика и анимированный револьвер с вращающимся барабаном и отдачей. Это только косметика, без изменения урона или механики.
- Одноцветные, градиентные, пульсирующие и переливающиеся никнеймы со свечением.
- Онлайн-список пользователей Lunacy.
- Роли `User`, `Tester`, `Admin`, `Creator` и выдача стилей/визуалов по `@handle`.
- Персональные ключи доступа для подтверждения админ-прав.
- Настройки FPS визуалов и чёткости canvas. По умолчанию выбран экономный режим 30 FPS.

## 1. Запустите сервер

Нужен Node.js 20 или новее. Внешние npm-зависимости не требуются.

```bash
cd server
npm start
```

Сервер слушает порт `8787`. При первом запуске он создаёт:

- `server/data/users.json` — пользователи, роли, никнеймы и визуалы;
- `server/data/private.json` — секретный ключ первого входа владельца и pepper для хешей.

**Не публикуйте `private.json` и не отправляйте его другим пользователям.**

Для Docker:

```bash
cd server
docker compose up -d --build
docker compose logs lunacy
```

Ключ первого входа будет выведен в лог и сохранён внутри volume. Можно заранее задать свой длинный случайный ключ через переменную `OWNER_BOOTSTRAP_KEY`.

## 2. Установите расширение

1. Откройте `chrome://extensions` или `edge://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение».
4. Выберите папку **`extension`** внутри проекта.
5. Нажмите иконку Lunacy рядом с адресной строкой:
   - адрес сервера для локальной проверки: `http://localhost:8787`;
   - при желании укажите `cleverok` в поле ручного handle.
6. Откройте или обновите `https://mope.io/`.

## 3. Получите права владельца

1. В HUD откройте вкладку **«Админ»**.
2. Убедитесь, что во вкладке «Онлайн» указан `@cleverok`.
3. Введите ключ первого входа из `server/data/private.json`.
4. Нажмите **«Подтвердить права»**.

После этого откроются список пользователей, выдача ролей, настройки никнеймов и визуалов, а также генерация ключей.

## Выдача роли или никнейма

1. В админке укажите handle вида `@user-a1a559ff38d09716` или выберите пользователя из списка.
2. Если игрока сопоставляют по нику в мире, заполните поле «Игровой ник» точно как в mope.io.
3. Выберите роль, стиль, два цвета, силу свечения и разрешённые визуалы.
4. Нажмите **«Выдать»**. Клиенты получат изменения при следующем heartbeat, обычно в течение 20 секунд.

Кнопка **«Создать ключ»** выдаёт новый персональный ключ и заменяет старый. Он нужен для входа с правами, а не для обычного использования визуалов.

### Права ролей

- **User:** обычные визуалы и назначенный никнейм.
- **Tester:** отдельная роль и стартовый пресет; админ-функций нет.
- **Admin:** просмотр пользователей, выдача `User`/`Tester`, настройки их стилей и ключи для них.
- **Creator:** все возможности, включая выдачу `Admin` и `Creator`.

## Как сделать сервер действительно общим

Запустите `server` на своём постоянном сервере с Docker, сохраните volume `/app/data` и настройте HTTPS через обратный прокси. Затем каждый пользователь указывает публичный адрес вида `https://lunacy.example.com` в иконке расширения. Проект сам по себе не развёрнут на внешнем хостинге: без запущенного общего сервера он работает локально.

Для production рекомендуется HTTPS. Для локального сервера предусмотрены CORS и Private Network Access заголовки.

## Управление и оптимизация

- **N** — скрыть/открыть HUD; когда панель скрыта, остаётся маленькая кнопка `L`.
- Перетаскивание — за верхнюю полосу HUD; позиция сохраняется.
- Колесо мыши — игровой зум с расширенным диапазоном.
- FPS визуалов: 20/30/60.
- Чёткость canvas: 1×/1.5×/2×.
- Один canvas для всех эффектов, отсечение кадров по FPS, остановка отрисовки в скрытой вкладке, heartbeat раз в 20 секунд.

## Важные ограничения

- Расширенный рендер убирает лишнее клиентское отсечение, но не может показать объекты, которые сервер mope.io вообще не прислал.
- Цветные ники в игровом мире видны пользователям Lunacy и сопоставляются по игровому имени. Это не изменение официального никнейма на сервере mope.io.
- У mope.io нет использованного здесь публичного OAuth. Гостевой handle является самоидентификацией, поэтому **все привилегированные действия требуют отдельного секретного ключа**.
- Патч зума проверен на актуальной структуре клиента на момент сборки. Если разработчики mope.io сменят её, расширение безопасно запустит оригинальный клиент: HUD останется, а расширенный зум может потребовать обновления сигнатур в `extension/patch-core.js`.
- Установка рассчитана на распакованное расширение. Публикация в Chrome Web Store потребует отдельной проверки правил магазина, поскольку адаптер получает текущий код страницы игры.

## Проверки

```bash
cd server
npm test

cd ../extension
node --test tests/patch-core.test.cjs
node --check content.js
```

Покрыты вход владельца, запреты ролей, выдача никнеймов/визуалов, обработка ошибок, патч зума и относительные импорты. HUD, онлайн-вход создателя и клавиша N дополнительно проверены в Chromium.

## Структура

```text
Lunacy/
├── extension/       # Расширение Chrome/Edge
│   ├── content.js   # HUD, визуалы, онлайн-клиент и админка
│   ├── patch.js     # Безопасный адаптер текущего клиента
│   ├── patch-core.js
│   └── popup.html   # Адрес сервера и ручной handle
└── server/          # Node.js API без внешних зависимостей
    ├── index.js
    ├── Dockerfile
    └── test/
```
